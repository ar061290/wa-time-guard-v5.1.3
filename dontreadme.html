What it does

Time Guard gives you eight minutes on WhatsApp Web, then takes the screen away for forty-two. It is not a blocker. It is a metronome: use it, get pulled out of it, go do the thing you were avoiding, come back later.

Tab in view and chat open → 8:00 usage → Esc ×3 → 42:00 blackout + quote → Idle, waiting again

The rules, exactly

  • The eight minutes start only when the WhatsApp tab is in view and a chat is open, at the same moment. Either one alone does nothing.
  • Once started, those conditions stop mattering. Closing the chat, switching tabs or switching windows changes nothing. They are start conditions, not run conditions.
  • At 8:00 the blackout is painted. No reload.
  • If a chat was open at that moment, the blackout opens with a compose box for the first 4 minutes: one message, sent into that chat, with three editable presets a click away. Escape is held back until the message is sent or the 4 minutes lapse. With no chat open, Escape fires three times first, exactly as before, so WhatsApp is back on the chat list.
  • The blackout runs 42:00 and then clears itself. The eight minutes do not restart — the start conditions must be met again.
  • The 8 minute allowance accumulates only while at least one web.whatsapp.com tab exists; close the last one and it freezes exactly where it was. The 42 minute blackout runs on the wall clock and never pauses, so closing the tab cannot bank lockout time.
  • EMERGENCY: eight multiple-choice questions, six correct, and the whole thing switches off for two hours or until you turn it back on. The two hours are never displayed.

Product requirements

Problem

Messaging does not fail loudly. It fails as a slow leak: eight minutes at a time, six times an evening, and the essay never gets opened. Blockers that simply deny access get uninstalled within a week, because at some point you genuinely do need to reply to someone.

Approach

Ration rather than deny. A short, generous window, followed by a long, non-negotiable gap, with an escape hatch that costs enough attention to be worth using only when it matters.

Rules the interface follows

  • No card inside a card. Every surface sits directly on the base background. Sections are separated by a single hairline, never by a nested container.
  • Two rectangles, fixed positions. Usage is always on the left, blackout always on the right. Neither ever disappears. A timer that is not running simply shows its full value, dimmed; the live one gets a coloured border.
  • Numbers are the loudest thing on screen. Tabular figures at 28px so the seconds do not wobble as they count.
  • One destructive-looking control. EMERGENCY is the only element in alert red, and it turns green when it becomes ENABLE GUARD.
  • The quiz gets its own tab. Answering is a full-attention task, the question crops are pages from the original papers and need the width, and a separate tab means nothing else on screen is competing for the decision.

The blackout screen

Two lines, vertically centred, nothing else. The quote sits in the larger sans face, the pushups line beneath it in italic serif at roughly 60% of the size — different enough to read as a separate voice, close enough to belong to the same screen. Both use the chosen text colour. The count updates on the minute, so it reads as a slow burn rather than a stopwatch.

Copy

Failure states never say "denied". A short quiz score is a fact, not a judgement: Too few correct: 4 of 8. The status line is written from the user's side of the screen — "Waiting — open WhatsApp and a chat", not "State: IDLE".

How the code works

The state machine

The service worker owns everything. The page and the popup only report and render.

IDLE ──(tab in view AND chat open)──▶ ACTIVE ──(8:00 elapsed)──▶ ESCAPING
                                                                      │ Esc ×3
                                                                      ▼
IDLE ◀──────────────(42:00 elapsed, quote index + 1)────────────── BLOCKED

Why timestamps instead of counting

Chrome suspends MV3 service workers aggressively, and background tabs throttle setInterval. Nothing counts ticks. State is stored as:

{ phase, accumulatedMs, runningSince, quoteIndex, bypassUntil }

elapsed = accumulatedMs + (runningSince ? now - runningSince : 0)

Pausing writes accumulatedMs = elapsed and clears runningSince. Resuming sets runningSince = now. The worker can die at any moment and wake up with the arithmetic still correct.

Pause on close, not on switch — and only the allowance

chrome.tabs.query({url: 'https://web.whatsapp.com/*'}) answers one question: does a WhatsApp tab exist? That is the entire pause condition, and it applies to the ACTIVE phase alone. Visibility and focus are only consulted for the start conditions, in considerStart.

BLOCKED deliberately ignores it. A lockout you can pause by closing the tab is not a lockout — you would close WhatsApp, do something else for forty minutes, come back and still owe the full forty-two. So the blackout keeps its runningSince set no matter what, and evaluate restores it if it ever finds it cleared.

Firing on time

Three independent triggers, because any one of them can be delayed:

  1. A chrome.alarms entry at the exact deadline.
  2. A setTimeout in the page, scheduled from the absolute deadline.
  3. A one-second poll in the page that compares Date.now() to the deadline.

Whichever fires first sends DEADLINE; the worker recomputes and ignores it if it was early. A one-minute reconcile alarm sweeps up anything else.

The one message

Cutting someone off mid-sentence for forty-two minutes is rude, and rudeness is what makes people uninstall a tool like this. So the blackout opens with a compose box whenever a chat was open at the moment the allowance expired. The window is bounded three ways: four minutes, one message, and the Escapes fire the instant either limit is reached. Because the crop of the conversation is already hidden behind the overlay, the box is the only thing you can act on — you can excuse yourself, but you cannot keep talking.

The text is inserted into WhatsApp's editor with execCommand('insertText'), which raises the same input events the editor listens for, and sent by clicking its own send control rather than faking a keystroke.

Escape, honestly

Extensions cannot generate trusted keystrokes without the debugger API. The content script dispatches full keydown / keypress / keyup Escape events at the focused element, document and window, with keyCode and which patched onto the event object because they are not settable through the constructor. If a future WhatsApp build ignores synthetic keys, fallbackCloseChat() clicks the back control instead.

The icon is a canvas

The worker draws the number into an OffscreenCanvas at 16, 32, 48 and 128 px and hands the ImageData to chrome.action.setIcon. Green with white digits during usage; the blackout's own colours during the blackout; grey while a bypass is active. The page draws the same thing into a 64px canvas and pushes it into a <link rel="icon">.

The title, without stepping on WhatsApp

WhatsApp rewrites document.title whenever the unread count changes. A MutationObserver on the <title> element records every value the extension did not write itself as the new base, strips any existing suffix, and re-appends the current seconds. The unread prefix survives untouched: (3) WhatsApp Web (47).

Quotes

8,000 lines ship as JSON and are read by the worker only, so the page never carries the payload. The index advances when WhatsApp is closed entirely and when a blackout completes, so you rarely see the same line twice in a week.

All 8,000 quotes

Every line is original to this extension and shipped offline. The blackout shows the one at the stored index; the index advances when WhatsApp is closed and when a blackout ends.

    MCQ bank & answers

    Two banks. EMERGENCY splits into ESAT and IOQM. The ESAT bank is multiple choice; the IOQM bank is 211 questions from IOQM and PRMO papers whose answers are integers 00–99, so those are typed rather than picked. Each bank keeps its own attempt log, its own four records and its own CSV and PDF downloads, so the timings never mix. The condensed-version gate on this page always draws from the ESAT bank.

    515 maths and physics questions from the ENGAA and NSAA Section 1 past papers (2016–2023 plus specimens). Chemistry and biology were dropped; everything else was kept, including diagram questions. Each one is a crop of the original page — stem, figure, table and options exactly as printed — so surds, fractions, graphs and circuits all survive. The answer buttons are the option letters.

    237 questions appear in more than one paper; the repeats were removed, and the fact that every duplicate pair agreed on its answer letter is the check that the keys are aligned. The one paper whose key disagreed with its twin (the 2020-format NSAA specimen) was dropped entirely.

    Eight are drawn at random each time EMERGENCY is used, with the options shuffled. Correct answers are marked.

    What it does

    • Tab in view and a chat open starts an 8 minute allowance.
    • After that: Escape ×3, then a 42 minute blackout carrying a quote.
    • Blackout ends → idle. The allowance does not restart on its own.
    • Allowance pauses when every WhatsApp tab is shut; the blackout never pauses.
    • Tab and window switching pause nothing. No page reload at any point.

    Product requirements

    • Ration attention rather than deny it, so the thing survives past week one.
    • Short window, long gap, one escape hatch that costs real effort.
    • Start conditions are initialisation only; they never pause a running timer.
    • One message out is allowed, because vanishing mid-sentence is what gets tools uninstalled.
    • Tamper resistance is explicitly out of scope.

    UI / UX

    • WhatsApp's own dark palette, with a light mode that inverts surfaces only.
    • No card inside a card; sections divide with hairlines.
    • Usage left, blackout right, fixed positions, neither ever hidden.
    • Tabular figures so the seconds do not wobble.
    • The quiz takes a whole tab; question crops need the width.

    How the code works

    • The service worker owns everything; page and popup only report and render.
    • State is {phase, accumulatedMs, runningSince, quoteIndex, bypassUntil}.
    • Elapsed time is derived from timestamps, so the worker can be killed at any moment.
    • Three independent triggers fire a transition: an alarm, a page timeout, a 1 s poll.
    • Escape is synthetic (keydown/keypress/keyup, keyCode patched on); a back-button click is the fallback.
    • The icon is drawn per minute into an OffscreenCanvas.
